# 最终版验收清单（手动测试指引）

> 环境准备：`node server/index.js`（已配 server/.env）+ 微信开发者工具导入本仓库 + 勾选"不校验合法域名"。
> 无 Key 演示：`node server/index.js --mock`（识别/小票模式返回演示数据；聊天需真实 Key）。

## 1. AI 识别主线

- [ ] 添加页 →「拍食物」→ 拍摄/选择食物照片 → 出现"AI 识别中"加载 → 结果行（名称/分区/天数可改）→ 保存单项与"全部保存"
- [ ] 保存后首页出现对应卡片，剩余天数/进度条/状态色正确
- [ ] **每条识别结果有「🏠 储存建议」行：如"推荐冷藏7天 · 常温2天 · 冷冻30天"，推荐分区标"推荐"，不推荐方式标"不建议"（Z1）**
- [ ] AI 给出的天数若超数据库范围，行上出现"已按数据库校正"标
- [ ] 「拍小票」模式 → 选小票图 → 多条食品结果（tips 显示为"备注："）→ 全部保存
- [ ] 识别中再次点照片/重试 → 不会发起第二次请求
- [ ] >6MB 大图 → 自动压缩后继续识别（不再直接报错）

## 2. AI 助手聊天（Z4）

- [ ] 首页右上「🤖 助手」进入聊天页
- [ ] 输入"我买了鸡蛋和牛奶" → AI 回复 + 绿色"✓ 已添加 鸡蛋/牛奶"执行标签 → 首页清单出现
- [ ] 输入"西红柿吃完了，帮我删掉" → "✓ 已删除 西红柿" → 清单移除；删除不存在食物 → 红色"✕ 未找到：xx"
- [ ] 点 📷 附一张食物照片 + "刚买的这个" → AI 识别并自动添加
- [ ] 问"牛奶应该怎么保存？" → 直接文字回答，不产生增删
- [ ] 快捷指令 chip 点击即填充；对话可连续多轮（助手记得库存）

## 3. 菜谱（Z3）

- [ ] 首页「可以做的菜」→ 右上「全部菜谱 ›」进入菜谱页
- [ ] 每道菜有徽标：「不缺料」绿 /「缺 n 样」黄 /「还缺全部」灰；用料按有绿缺灰着色
- [ ] 点卡片展开：用料清单（✓/✕）、做法要点、缺料提示（引导去清单）
- [ ] 搜索"鸡蛋"只显示相关菜谱；标题统计"共 X 种搭配 · Y 道不缺料"

## 4. 营养成份（Z2）

- [ ] 任意食物详情页底部有「🥗 营养成份（每100g可食部）」卡：千卡/蛋白质/脂肪/碳水/纤维
- [ ] 常见食物（牛奶/苹果/鸡蛋等）标注"实测均值"；冷门食物标注"按类别估算"
- [ ] 数值在合理范围，底部有"仅供参考"说明

## 5. 清单管理

- [ ] 首页统计（已过期/即将到期/在库总数）正确
- [ ] 分区筛选（全部/冷藏/冷冻/常温）与类别筛选（展开 ▼）组合生效
- [ ] 「今天该吃」横滑条：过期/临期优先，点击进详情
- [ ] 卡片点击进详情；长按 → 标记已食用/删除快捷操作
- [ ] 「批量管理」→ 点选多张（绿框勾选）→ 全选/清空 → 批量已食用 / 批量删除（过期项计入浪费）

## 6. 详情页功能

- [ ] 「🔓 标记已开封」→ ActionSheet 选天数（首项为分类建议：乳制品3/熟食2/其他7）→ 顶部出现开封徽标，剩余天数按开封窗口重算
- [ ] 已开封后再编辑天数 → 更新开封窗口而不是被覆盖
- [ ] 「📦 剩余量」→ 选"见底" → 卡片出现红色"见底"角标
- [ ] 「🔀 转移分区」→ 选目标分区（含建议天数）→ 有效期重算，出现"🔀 转移记录"

## 7. 采购清单

- [ ] 首页右上「🛒 清单」进入
- [ ] 手动输入加入；重复名不重复加入
- [ ] "最近吃完的"点击补货
- [ ] 勾选（○→●）进"已买"区 → 「全部放入冰箱」→ 按数据库建议入库并从清单移除（土豆等自动进常温）

## 8. 统计（设置页）

- [ ] 在库/已食用/浪费/¥及食估算 四格数据正确
- [ ] 未来7天到期预测柱状图与实际到期分布一致（过期/今天/明天…7天）

## 9. 其他

- [ ] 设置页：AI 模式切换；输入不带协议的地址自动补 http:// 并提示；「测试连通性」显示模型名与 Key 尾号
- [ ] 数据导出（剪贴板）→ 清空数据场景 → 导入恢复（id 冲突跳过）
- [ ] 启动小程序若有过期/临期 → 弹一次性提醒
- [ ] tabBar 三个图标显示正常，选中态墨绿

## 回归保障

`node --test tests/*.test.js`（68 例）与 `node tools/validate.js` 全绿是每次提交的门槛；其中静态校验包含：页面四件套完整性、事件处理函数绑定核查、数据绑定根标识符核查（wx:for 作用域追踪）。
